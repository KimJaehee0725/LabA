# 00. v0.2 and v0.3 Roadmap

## 목표 정의

v0.2는 구현 단계다. 각 모듈별로 실제 파일을 만든다.

v0.3는 smoke test 단계다. 모든 1차 모듈이 한 서버에서 올라오고, 핵심 사용자 흐름이 최소 1회씩 검증되어야 한다.

## v0.2 범위

v0.2에서 만든다:

- `/srv/lab-platform` 기준 디렉토리 생성 스크립트
- `.env.example`
- `.gitignore`
- core compose
- Nginx compose와 snippets
- Authentik compose와 blueprint skeleton
- 서비스별 compose skeleton
- 서비스별 nginx server block
- DB/user/bucket bootstrap script
- backup script skeleton
- 운영 runbook 초안

v0.2에서 하지 않는다:

- 실제 secret commit
- 실제 인증서 commit
- HA 구성
- full monitoring stack
- HWP viewer 구현
- Overleaf LDAP SSO
- Nextcloud MinIO primary storage migration
- 자동화 도구 Ansible/Terraform 도입

## v0.3 Smoke Target

v0.3에서 통과해야 하는 최소 smoke flow:

1. Nginx가 모든 placeholder host에 대해 올바른 upstream으로 proxy한다.
2. Authentik admin 로그인과 일반 사용자 로그인, MFA enrollment가 된다.
3. Gitea OIDC 로그인, repo 생성, Git push, LFS push가 된다.
4. Plane OIDC 로그인, workspace 접근, work item 생성, 파일 첨부가 된다.
5. MLflow UI는 인증 없이는 막히고, 인증 후 experiment와 artifact upload가 된다.
6. Nextcloud OIDC 로그인, 파일 업로드, Collabora 문서 편집이 된다.
7. Overleaf admin 생성, 사용자 초대, LaTeX compile이 된다.
8. Postgres dump, MinIO bucket listing, Gitea dump, Nextcloud backup dry-run이 된다.

## 의존성 그래프

```text
host prep
  -> core networks
  -> postgres / redis / minio
  -> nginx skeleton
  -> authentik
    -> gitea
    -> plane
    -> mlflow forward auth
    -> nextcloud oidc
    -> minio console oidc
  -> collabora after nextcloud
  -> overleaf independent after nginx/core
  -> backup scripts after each data owner exists
```

## 구현 순서

| 순서 | 모듈 | 이유 |
|---:|---|---|
| 1 | Core infrastructure | 모든 서비스의 기반 |
| 2 | Edge Nginx/TLS | 외부 노출과 내부 routing 기준 |
| 3 | Authentik | 이후 OIDC/Forward Auth의 기준 |
| 4 | Gitea | config와 문서/코드 보관 기반 |
| 5 | Plane | 프로젝트 관리와 위키 기반 |
| 6 | MLflow | 실험 추적, artifact store 검증 |
| 7 | Nextcloud + Collabora | 파일/문서 협업 |
| 8 | Overleaf CE | 논문 편집, 별도 Mongo/Redis |
| 9 | Backup/restore | 운영 안정성 확인 |
| 10 | v0.3 smoke test | 전체 연동 검증 |

## 공통 Definition of Done

각 모듈은 다음을 만족해야 완료로 본다.

- compose config가 렌더링된다.
- 컨테이너가 `up -d` 후 healthy 또는 정상 로그 상태다.
- 외부로 의도하지 않은 port가 publish되지 않는다.
- 핵심 HTTP endpoint가 Nginx 경유로 응답한다.
- 서비스별 write operation이 1회 성공한다.
- 백업 대상이 문서화되어 있다.
- rollback 또는 stop 절차가 문서화되어 있다.

## 주요 리스크

| 리스크 | 대응 |
|---|---|
| 공식 compose와 직접 작성 compose가 diverge | 공식 compose/문서 링크와 diff 절차를 runbook에 둔다 |
| OIDC redirect URI 오류 | 서비스별 redirect URI 표를 `.env.example`과 blueprint에 함께 둔다 |
| Docker socket 권한 과다 | Authentik outpost는 수동 배포를 기본안으로 둔다 |
| MinIO root key 남용 | 서비스별 access key/policy bootstrap을 v0.2 backlog에 포함한다 |
| Nextcloud primary storage 결정 지연 | v0.2 전 로컬 디스크 기본안을 확정한다 |
| MLflow API 자동화 인증 미정 | v0.3 smoke는 UI 인증과 내부 artifact upload까지만 잡는다 |
