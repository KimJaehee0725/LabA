10주 pilot을 기준으로 하되, Huly 검증을 앞당긴다

원래 임시 계획은 인프라부터 순차 진행하는 형태였다. 이번에는 Huly가 실제 요구를 만족하는지 빨리 판단하기 위해 Edge/Auth 직후 Huly pilot을 먼저 통과시키고, 그 뒤 storage, HF-like UI, Overleaf, 운영 자동화를 붙인다.

Dependency order

external readiness
  -> host skeleton
  -> school TLS and Nginx
  -> Authentik identity baseline
    -> Huly pilot
      -> Huly GitHub and migration smoke
    -> MinIO OIDC console
      -> HF-like UI MVP
    -> Overleaf account policy
  -> portal, backup, monitoring
  -> onboarding and production pilot

Phase exit policy

Pass

Gate checklist가 통과하고, runbook에 정상/중단/복구 절차가 남아 있으며, 다음 phase가 사용할 endpoint와 credential handoff가 정리되어 있다.

Conditional pass

핵심 flow는 통과했지만 문서화된 workaround가 있다. Huly OIDC 미지원 시 forward-auth로 pilot을 열고, 정식 SSO는 decision log에 남긴다.

Stop

보안 gate, 데이터 손실 위험, 인증 우회, 백업 불가가 발견되면 다음 phase로 넘어가지 않는다.
