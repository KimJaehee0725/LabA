기존 Grist/Plane/Nextcloud 방향은 archive branch에 보존하고, 이 계획은 새 runtime root와 새 branch에서 Huly를 중심 서비스로 검증한다. Huly는 연구실 위키, 채팅, 작업 관리, 일정, GitHub 연동의 1차 허브이며, MinIO와 HF-like UI는 모델/데이터셋 허브를, Overleaf CE는 논문 협업을 담당한다.

결론

이번 MVP에서 한다

  • 학교 도메인, 학교 SSL, 80/443 방화벽, 학교 SMTP를 운영 전제 조건으로 둔다.
  • Authentik을 단일 SSO 게이트웨이로 두고 2FA와 초대 링크 가입을 기본 정책으로 삼는다.
  • Huly self-host를 먼저 올려 문서, 채팅, 이슈, 캘린더, Gantt, GitHub App 연동을 검증한다.
  • MinIO를 자체 HDD 위 S3 호환 저장소로 구성하고, HF-like UI MVP를 별도 앱으로 만든다.
  • Overleaf CE는 초기에는 별도 계정 방식으로 시작하고 템플릿과 컴파일 검증을 우선한다.
  • 백업, 모니터링, 온보딩 문서까지 정식 pilot의 완료 조건에 포함한다.

이번 MVP에서 하지 않는다

  • 이전 `/srv/lab-platform` runtime 구조를 이어 쓰지 않는다.
  • Gitea를 재도입하지 않는다. GitHub 연동은 Huly GitHub App을 기준으로 한다.
  • Plane, Nextcloud, Grist를 기본 활성 서비스로 두지 않는다.
  • Overleaf CE OIDC/LDAP SSO를 첫 구현의 필수 조건으로 잡지 않는다.
  • HF Hub API 완전 호환, 대형 업로드 UI, public community 기능은 MVP 이후로 분리한다.
