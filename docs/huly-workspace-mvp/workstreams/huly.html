Huly가 연구실의 1차 업무 허브가 될 수 있는지 먼저 검증한다

Huly pilot은 전체 전환의 핵심 판단 지점이다. 위키, 채팅, 이슈, 캘린더, Gantt, GitHub 연동, Notion import sample이 통과하면 Plane/Nextcloud를 기본 서비스로 재도입하지 않고 Huly 중심으로 간다.

Phase 3 deployment artifacts

Runtime

  • `deploy/compose/huly/docker-compose.yml`: Huly v0.7 self-host services without upstream nested Nginx.
  • `deploy/env/30-huly.env.example`: Huly server-only settings and integration placeholders.
  • `deploy/nginx/conf.d/20-huly.conf`: edge routes for `/_accounts`, `/_transactor`, `/_collaborator`, `/_github`, `/_calendar`, and `/files`.
  • `deploy/runbooks/phase3-huly.md`: server execution, fallback, rollback, and full-pass criteria.

Validation

  • `23-check-phase3-huly-preflight.sh`: env, OIDC callback, compose, and integration readiness.
  • `30-check-huly.sh`: container health, no direct host ports, edge reachability, OIDC discovery.
  • `31-bootstrap-huly-workspace.sh`: deterministic manual seed checklist.
  • `32-check-huly-pilot.sh`: report gate for full-pass or documented conditional-pass.

Workspace seed

Channels

  • `#general`: 전체 공지와 운영 안내.
  • `#research`: 연구 토론과 실험 공유.
  • `#paper`: 논문 작업, 리뷰, 마감.
  • `#infra`: 서버와 도구 운영.
  • `#random`: 비공식 대화.

Projects

  • `Experiments`: 실험 계획, 결과, 재현성 이슈.
  • `Papers`: 논문별 milestone, reviewer response, template task.
  • `Infrastructure`: self-hosted stack 운영과 incident task.
  • `Datasets`: dataset 준비, 권한, 업로드, QA.
  • `Onboarding`: 멤버와 게스트 초대 체크리스트.

GitHub App setup

  1. GitHub organization 또는 target account에 Huly용 GitHub App을 만든다.
  2. Webhook URL은 실제 Huly 배포 버전에 맞춰 고정한다.
  3. 권한은 Metadata read, Issues read/write, Pull requests read/write, Contents read로 시작한다.
  4. App ID, private key, webhook secret은 server-only env에 저장한다.
  5. 연결 repo를 하나만 선택해 issue create/update/close와 PR merge event를 테스트한다.
  6. 성공 후 연구실 주요 repo를 단계적으로 추가한다.

Calendar setup

  • Google OAuth web application redirect URI는 `https://huly.lab.example.ac.kr/_calendar/signin/code`이다.
  • Calendar service는 Huly `calendar` profile과 `huly-mongodb`를 함께 사용한다.
  • credential JSON은 `/opt/lab-stack/env/30-huly.env`의 `HULY_GOOGLE_CALENDAR_CREDENTIALS`에만 저장한다.
  • event create/update sync가 확인되어야 Phase 3 full-pass로 본다.

Gantt and fallback decision

Pass criteria

  • issue에 start/end date 또는 equivalent field를 줄 수 있다.
  • timeline/Gantt view가 self-hosted에서 표시된다.
  • dependency 또는 milestone grouping이 논문/실험 관리에 충분하다.
  • 브라우저 reload 후에도 view state가 유지된다.

Fallback

  • Gantt가 self-hosted에서 막히면 Plane 보완 배포를 별도 decision으로 연다.
  • Huly는 docs/chat/GitHub hub로 유지할 수 있는지 판단한다.
  • Plane 재도입 시 task canonical 중복을 피하도록 Huly issue scope를 줄인다.
  • Grist는 이 단계에서 바로 재도입하지 않는다.

Notion migration sample

  1. 기존 Notion에서 핵심 페이지 5개만 Markdown and CSV로 export한다.
  2. 개인정보나 secret이 없는지 export zip을 확인한다.
  3. Huly import 기능 또는 수동 copy로 Lab handbook 하위에 넣는다.
  4. 표, 링크, 이미지, task checkbox, code block 품질을 기록한다.
  5. 마이그레이션 비용이 크면 핵심 페이지만 정리하고 나머지는 archive-readonly로 남긴다.

Huly exit gate

Huly pilot은 기능별 체크만으로 끝내지 않는다. 실제 연구실 멤버 2명 이상이 1주일 동안 회의 note, task update, GitHub issue, file attachment를 사용하고, 막힌 지점을 decision log에 남긴 뒤 다음 phase로 넘어간다.
