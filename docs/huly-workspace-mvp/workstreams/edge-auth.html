외부 공개면은 작고, 인증 정책은 엄격하게

학교 SSL 인증서와 Nginx가 모든 traffic의 입구가 된다. Authentik은 2FA, 초대 링크 가입, 그룹 기반 OIDC claim, 관리자 알림을 제공한다.

Prerequisites

항목 요청 내용 완료 증거
도메인 `lab.example.ac.kr`와 wildcard subdomain 또는 필요한 A records `dig` 결과가 서버 IP로 resolve
SSL `*.lab.example.ac.kr`와 apex host를 포함하는 학교 인증서 crt, key, ca bundle 수령 및 fingerprint 기록
방화벽 Inbound TCP 80, 443 허용 외부 network에서 curl 가능
SMTP 학교 SMTP host, port, auth 방식, from address 승인 test mail 수신
서버 Ubuntu 24.04 LTS, Docker, compose plugin, fail2ban, ufw `docker run hello-world`, `ufw status`, `fail2ban-client status`

Nginx baseline

Common snippets

  • `ssl-school.conf`: certificate and private key path.
  • `security-headers.conf`: HSTS, no sniff, frame policy, referrer policy.
  • `proxy-params.conf`: Host, real IP, forwarded headers.
  • `websocket.conf`: upgrade headers for Huly and Overleaf.
  • `upload-large.conf`: large object upload limits for HF and S3 surfaces.

Security defaults

  • HTTP always redirects to HTTPS.
  • `server_tokens off`.
  • login/API rate limits.
  • service upstreams bind to `127.0.0.1` or private Docker network only.
  • no service publishes an unexpected public port.

Authentik baseline

영역 구체 작업 DoD
Groups `lab-admins`, `lab-members`, `lab-guests` 생성 테스트 사용자 3명에 group claim 확인
2FA TOTP stage를 기본 login flow에 binding 신규 사용자 첫 로그인에서 2FA 등록 강제
Enrollment self-signup off, invitation-only enrollment flow 구성 초대 링크 없이 가입 불가, 초대 링크로 가입 가능
Email SMTP 설정, 가입/실패/백업 알림 발신 계정 확정 테스트 메일과 가입 알림 수신
OIDC providers Huly, MinIO, HF UI, optional portal/status client 생성 client id/secret은 server-only env에 저장
Forward-auth fallback Huly OIDC가 부족할 경우 Nginx forward-auth route 준비 로그인 없이 Huly 접근 차단

Implementation order

  1. Repo에 `deploy/compose/authentik`, `deploy/nginx`, `deploy/env` skeleton을 Huly branch 기준으로 정리한다.
  2. 서버에 `/opt/lab-stack/certs`를 만들고 학교 인증서 파일을 배치한다.
  3. Nginx를 최소 redirect + auth host만으로 먼저 올린다.
  4. Authentik compose를 올리고 initial admin을 만든다.
  5. 2FA, groups, invitation flow, SMTP, notification을 설정한다.
  6. Huly, MinIO, HF UI용 OIDC provider를 생성하고 redirect URI를 고정한다.
  7. Edge/Auth gate를 통과한 뒤 Huly workstream으로 넘어간다.

Open details

실제 redirect URI는 배포하는 Huly self-host 버전의 문서를 확인한 뒤 고정한다. 버전별로 OIDC endpoint 지원 상태가 달라질 수 있으므로, Huly OIDC가 불안정하면 MVP에서는 Authentik forward-auth로 외부 접근을 보호한다.
