외부 공개면은 작고, 인증 정책은 엄격하게

학교 SSL 인증서와 Nginx가 모든 traffic의 입구가 된다. Authentik은 2FA, 초대 링크 가입, 그룹 기반 OIDC claim, 관리자 알림을 제공한다. Active 절차는 staging-first Phase 2 runbook과 staging report에 기록한다.

Active Phase 2 gate

`deploy/runbooks/edge-nginx.md`와 `deploy/runbooks/authentik.md`는 v0.x historical reference다. Phase 2 실행자는 `/opt/lab-stack`, `labstack_public/backend/data`, public ports 80/443, server-only secrets 정책을 기준으로 staging에서 먼저 검증한다.

Nginx baseline

Common snippets

  • `ssl-school.conf`: certificate and private key path.
  • `security-headers.conf`: HSTS, no sniff, frame policy, referrer policy.
  • `proxy-params.conf`: Host, real IP, forwarded headers.
  • `websocket.conf`: upgrade headers for Huly and Overleaf.
  • `upload-large.conf`: large object upload limits for HF and S3 surfaces.

Security defaults

  • HTTP always redirects to HTTPS.
  • `server_tokens off`.
  • login/API rate limits.
  • service upstreams bind to `127.0.0.1` or private Docker network only.
  • no service publishes an unexpected public port.

Implementation order

  1. P2-A: Phase 0/1 evidence, `/opt/lab-stack`, `labstack_*`, domain, certificate, SMTP, secret policy를 확인한다.
  2. P2-B: Nginx를 최소 redirect + auth host만으로 staging에 올리고 TLS, redirect, public ports 80/443을 검증한다.
  3. P2-C: Authentik을 올리고 initial admin, admin 2FA, groups, invitation-only enrollment, SMTP를 검증한다.
  4. P2-D: Huly, MinIO, HF UI용 OIDC metadata와 redirect URI를 고정하고 generated secrets는 server env에만 저장한다.
  5. P2-E: `deploy/reports/phase2-edge-auth-staging.md`에 validation, rollback state, Phase 3 handoff를 남긴 뒤 Huly workstream으로 넘어간다.

Rollback and secrets

  • 문제가 생기면 삭제보다 stop을 우선한다: Authentik stop, Edge stop 순서로 중단한다.
  • `/opt/lab-stack/env`, `/opt/lab-stack/certs/private/staging.key`, Authentik data, Nginx/Auth logs는 incident owner가 분류할 때까지 보존한다.
  • real env, TLS private key, bootstrap token, generated OIDC client secret은 repo, report, issue, chat에 쓰지 않는다.
  • route 하나만 문제면 해당 `nginx/conf.d` 파일을 빼고 `nginx -t` 후 reload한다.

Open details

실제 redirect URI는 배포하는 Huly self-host 버전의 문서를 확인한 뒤 고정한다. 버전별로 OIDC endpoint 지원 상태가 달라질 수 있으므로, Huly OIDC가 불안정하면 MVP에서는 Authentik forward-auth로 외부 접근을 보호한다.
