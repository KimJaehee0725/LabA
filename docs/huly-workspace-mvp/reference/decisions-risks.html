결정은 작게 확정하고, 불확실성은 gate에서 닫는다

Huly 전환은 핵심 도구가 실제로 요구 기능을 만족하는지 확인해야 한다. 따라서 Huly OIDC, Gantt, GitHub sync, Notion migration 품질은 초기에 검증하고, 실패 시 fallback을 별도 decision으로 남긴다.

Accepted decisions

ID 결정 근거 영향
ADR-001 Huly를 1차 collaboration hub로 둔다. Notion 대체 요구가 문서, 이슈, 채팅, 캘린더, Gantt를 한 surface에 요구함 Plane/Nextcloud는 기본 배포에서 제외
ADR-002 Gitea를 쓰지 않고 GitHub App 연동을 기준으로 한다. 사용자가 GitHub/Slack 연동을 요구했고, 기존 계획에서 Gitea는 제외 결정됨 코드 canonical source는 GitHub
ADR-003 새 runtime root는 `/opt/lab-stack`로 둔다. `/srv/lab-platform`은 v0.3/v0.4 실험 흔적과 분리해야 함 배포 스크립트와 runbook path를 새로 정리
ADR-004 초대 링크 가입과 2FA를 기본 정책으로 한다. 외부 공개 서비스이고 게스트 가입 악용을 막아야 함 self-signup은 off, admin notification 필요
ADR-005 Overleaf CE는 MVP에서 별도 계정으로 시작한다. CE SSO integration cost가 높고 논문 협업 검증이 우선임 운영자가 계정을 발급하되, 동일 email 사용
ADR-006 HF-like UI MVP는 조회/다운로드 중심으로 시작한다. 대형 업로드와 HF API 호환은 구현 리스크가 큼 v1에서 multipart upload, v2에서 API compatibility 검토

Open decisions

ID 결정해야 할 것 닫는 시점 판단 기준
OD-001 Huly OIDC를 직접 쓸지, Authentik forward-auth로 보호할지 HULY-03 사용 중인 Huly self-host 버전의 OIDC 안정성
OD-002 Huly Gantt가 Plane 없이 충분한지 HULY-05 논문/실험 milestone pilot에서 실제 사용 가능 여부
OD-003 Grist를 structured DB 보완재로 재도입할지 HF MVP 이후 실험 registry, review queue, resource DB가 Huly/HF metadata로 부족한지
OD-004 HF-like UI upload를 v1에 포함할 범위 HF-03 이후 연구자가 CLI/SDK upload로 충분한지, browser upload 요구가 큰지
OD-005 Slack 병행 운영 종료 조건 Week 10 Huly 채팅과 알림이 실제 멤버 workflow에 들어왔는지
